# 班级小喇叭 · Class Speaker

老师在手机上发一条通知，教室电视立刻全屏弹出大字并朗读。教师端用网页，教室大屏端 / 学生端用电脑软件。

- 教师端（网页）：https://class-speaker-00500.app.workbuddy.host/
- 本仓库：GitHub Pages 只做「下载 + 入口」页，真正的应用前后端都在 WorkBuddy 云上
- 桌面端下载：右上角 **Code → Download ZIP**，解压后进入 `desktop` 文件夹

## 三个端

| 端 | 形态 | 怎么用 |
|---|---|---|
| 教师端 | 网页 | 手机/电脑浏览器打开，微信扫码登录；发文字、语音、对讲、图片，定时通知，点名 + 倒计时 |
| 教室大屏 | 桌面软件 | 教室电脑双击 `desktop/start-screen.vbs`，全屏显示；常驻执行定时广播（眼保健操、放学提醒） |
| 学生端 | 桌面软件 | 教室电脑双击 `desktop/start-student.vbs`，学生按住说话，老师端可回放 |

第一次打开会要求输入 **6 位绑定码**（教师在「班级」页顶部可以看到），绑定一次之后长期有效，不需要登录账号。

## 桌面端为什么不用网页

云端接口按来源域名校验，只有应用的发布域名和本机（localhost / file://）被放行。桌面端以本地文件方式运行，属于本机来源，所以能直接读写云端；而把同一份代码放在 github.io 上跑会被网关 403 拒绝。这也是这里用「网页 + 本地软件」混合形态的原因。

## 目录

```
index.html                 下载 & 入口页（GitHub Pages 首页）
desktop/
  start-screen.vbs / .bat  教室大屏启动器（无地址栏的独立窗口）
  start-student.vbs / .bat 学生端启动器
  screen.html              大屏页面
  student.html             学生端页面
  css/common.css
  js/                      大屏与学生端共用的前端逻辑
```

启动器优先找 Microsoft Edge（Win10/11 自带），找不到再找 Chrome，最后退回系统默认浏览器。`start-*.vbs` 是主启动器：没有控制台窗口、没有地址栏、大屏直接全屏；路径里有中文或空格也能正常打开。`start-*.bat` 是备用方案，只把页面交给系统默认浏览器打开。

## 说明

- 桌面端只是给浏览器套了一个应用窗口，所以电脑上需要有 Edge 或 Chrome。
- 大屏页要保持常开，定时广播靠它到点触发；电脑休眠会停。
- 首次使用大屏时点一下「启用声音并开始」，浏览器才允许自动朗读。
